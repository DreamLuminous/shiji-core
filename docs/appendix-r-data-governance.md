## R.1 数据治理目标

时己处理的数据具有特殊性质。它不是普通互联网数据。它可能包含：人生经历；家庭关系；工作项目；学习过程；情绪变化；健康相关信息；对未来的规划。因此，数据治理不能只考虑：“如何存储”。必须考虑：谁可以访问、为什么访问、访问后如何负责。

## R.2 数据治理核心原则

原则1：数据默认属于用户：系统中的所有经验数据：默认：用户所有。平台：不是拥有者。只是：服务提供者。

原则2：最小化收集：时己不应该问：“还能收集什么？”，而应该问：“实现功能最低需要什么？”，例如：记录功能：需要：文字。不需要：GPS。不需要：通讯录。不需要：摄像头权限。

原则3：用户主动授权：任何扩大数据使用范围的行为：必须：明确授权。例如：AI分析：第一次：询问。以后：用户可以关闭。

原则4：可撤回：授权：不是永久出售。用户任何时候：可以撤回。

## R.3 数据分类体系

建立：五级数据分类。

D0级：公开数据，特点：用户主动公开。例如：公开项目介绍。权限：公开。

D1级：普通个人数据，例如：普通笔记。学习记录。权限：用户本人。

D2级：敏感经验数据，例如：家庭经历。个人关系。权限：严格控制。

D3级：高度敏感数据，例如：健康相关。心理状态记录。权限：最高保护。

D4级：核心身份数据，例如：恢复密钥。身份认证。权限：后台服务不可读取；客户端仅在授权解锁后使用。

## R.4 数据生命周期管理

流程：产生；保存；使用；分析；分享；删除。

每一步：都有控制。

## R.5 数据产生阶段

### R.5.1 用户输入

用户创建：Moment。系统记录：

```json
{
"id":"001",
"content":"今天完成项目",
"time":"2027-01-01"
}
```

此时：属于用户数据。

## R.6 数据存储阶段

本地优先：默认：设备本地。存储：手机：SQLite。电脑：SQLite。浏览器：IndexedDB。

## R.7 数据加密制度

静态加密：At Rest Encryption。保护：设备丢失。

传输加密：In Transit Encryption。保护：同步过程。

## R.8 数据访问控制

设计：权限矩阵。

| 角色 | 访问范围 |
| --- | --- |
| 用户 | 全部自己的数据 |
| AI | 用户授权范围 |
| 服务器 | 密文 |
| 开发者 | 无用户内容 |
| 合作机构 | 明确授权内容 |

## R.9 AI数据治理

这是重点。

AI访问原则：AI不是默认拥有全部数据。流程：

流程：用户请求；权限判断；选择数据范围；生成分析；展示来源。

示例：用户：“总结我的学习变化。”，AI读取：学习相关记录。不会读取：私人记录。

## R.10 AI训练政策

明确：默认：用户数据不用于训练公共模型。原因：个人经验高度敏感。如果未来：用于改进模型。必须：单独授权。

## R.11 数据分享模型

设计：Share Permission。等级：S0：不分享。

S1：本人设备。

S2：指定人员。例如：医生。

S3：机构授权。

S4：公开。

## R.16 数据删除机制

用户拥有：删除权。删除回执应列明已处理对象、待同步设备与备份状态。删除流程：请求删除 → 确认 → 删除本地 → 删除同步数据 → 生成删除证明。

## R.17 数据导出机制

这是个人经验主权核心。用户必须可以：完整导出。格式：开放格式。例如：

```json
{
"moments":[],
"projects":[],
"attachments":[]
}
```

避免：平台锁定。

## R.22 隐私验收测试

发布前：必须测试。

Privacy 001：断网情况下：软件正常记录。结果：达到预期标准；实际状态待测试填写。

Privacy 002：查看数据库文件。结果：无法读取明文。

Privacy 003：关闭AI权限。结果：AI不能访问数据。

Privacy 004：删除账户。结果：检查当前设备、索引与同步服务的清理结果，离线设备与外部备份单独列明。

Privacy 005：导出数据。结果：用户获得完整副本。

## R.23 隐私透明中心

产品内建立：Privacy Center。展示：我的数据在哪里：答案：本地设备。

AI读取什么：答案：用户授权范围。

谁访问过：答案：访问记录。

如何删除：答案：一步操作。

## R.25 本附录总结

时己最大的隐私创新：不是，“我们承诺保护你的数据。”，而是，让系统设计本身减少需要相信系统的程度。传统模式：用户相信平台。时己模式：用户控制系统。这也是个人经验主权真正落地的基础。
