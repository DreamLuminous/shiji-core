# 1 项目概述

[返回总目录](../README.md)

返回目录  ·  阅读导航

## 1.1 项目背景

个人经历通常保存在记忆、日记、照片、书信和作品中，也可能由他人讲述。数字工具让记录更容易保存和检索，同时把资料分散在聊天平台、云相册、健康设备和其他服务中。当 AI 开始读取这些资料、生成总结和推测需求时，用户需要知道数据由谁保管、谁可以分析，以及自己能否修正或拒绝分析结果。时己围绕这些控制能力设计个人经验系统。

部分 AI 服务采用“用户输入、服务端处理、模型分析、返回结果”的流程。使用这类服务时，需要核查输入的处理和保留方式，并区分原始记录与模型解释。例如，用户写下“今天完成了一个困难的软件项目”，模型可能推测其具有自律或目标导向的特点。一次项目记录不足以支持稳定的人格结论；系统应展示依据和适用范围，让用户判断这种解释是否符合自己的经历。

时己将个人经验主权（Personal Experience Sovereignty）作为产品设计原则，要求用户能够控制记录的保存、分析、解释、分享和迁移。

## 1.2 个人经验主权定义

本章把个人经验主权归纳为数据、解释和分享三个层面。后文的记录权、迁移权、删除权等，是这三个层面的具体操作要求。

数据主权要求用户能够管理自己的文字、图片、视频、语音、标签和 AI 分析结果，并可导出、迁移和删除。默认保存在用户设备上；启用外部服务时，应明确说明保存位置和处理范围。这里的“主权”是本项目的设计目标，不替代具体服务协议中的权利约定。

解释主权要求 AI 分析保留来源和不确定性，用户可以确认、修正或拒绝。例如，AI 根据多条记录提出“你最近可能更关注长期项目”，用户可以补充“近期课程任务比较集中”。反馈作为用户解释保存，原始记录和模型输出仍保持各自来源。

分享主权要求用户选择接收对象、资料范围和用途。向医生、家人、机构或外部 AI 服务提供资料前，应展示发送清单并取得本次授权；默认关闭外部分享。

## 2.1 从记录到理解

时己把记录、回忆、理解、成长和协作组织成逐步扩展的能力链。先让用户可靠地留下经历，再帮助其检索、关联和回顾；AI 与专业协作在用户授权和基础数据能力成熟后加入。

记录阶段保存用户主动描述的事情。例如，用户在 2026 年 10 月 14 日写下“今天第一次完成数据库实验”。系统保存原话、来源和时间；这是一份用户自述，不自动等同于外部已核实事实。

回忆阶段帮助用户重新找到过去。例如，三年后搜索“第一次做软件项目”，系统返回首次开发示例图像项目、部署网站或发布代码的相关记录，并允许查看原文。

理解阶段帮助用户观察长期变化。例如，过去一年多次出现软件开发、隐私保护和开源项目记录，AI 可以提出“你的兴趣可能逐渐集中于技术创造”，同时列出支持记录和其他可能解释。

成长阶段支持用户主动复盘和调整。例如，用户注意到过去半年计划较多、完成记录较少，可以查看任务变化和相关经历。记录覆盖程度应同时说明，不能把未记录的活动直接计为未完成。

协作阶段在用户选择的范围内整理资料。例如，用户可以向医生提供过去半年的睡眠相关记录；共享范围限定于本次选定资料，其他个人记录继续保持私密。


# 3 产品定位

[返回总目录](../README.md)

返回目录  ·  阅读导航

## 3.1 它是什么

时己是一套本地优先、隐私保护优先的个人经验管理系统。软件承担记录、管理、检索和回顾；可选 AI 提供有来源的辅助解释。

## 3.2 它不是什么

日记是重要的记录入口。时己在记录基础上增加长期主题、项目关联、资料迁移和授权分析，帮助用户持续管理经历。

对话可以作为未来的辅助交互。系统的核心仍是可检索、可修正、可迁移的长期记录库，分析结果须回到相关记录核查。

Moment 硬件规划用于主动标记值得保留的瞬间，基础版不持续采集身体指标或环境信息。


# 6 软件 MVP 功能设计

[返回总目录](../README.md)

返回目录  ·  阅读导航

本章覆盖 MVP 系列的完整功能设计。Alpha 0.1 只交付基础文字闭环；0.2 增加图片、语音与标签；0.3 增加经验组织。功能清单表示待验收能力。

计划在 1 至 3 个月内完成可内测的基础软件。以下模块按版本逐步交付，每个模块的测试结果单独登记。

## 6.1 快速记录模块

快速记录模块应减少填写和整理步骤。用户先保存内容，标题、标签和项目关联可在回顾时补充。

0.1 支持文字；0.2 增加语音、图片和标签。硬件输入在软件基础能力稳定后独立验证，不占用首版开发范围。

首页显示日期、记录入口和最近记录。进入编辑器后直接输入正文，保存前不强制填写标题、分类或心情。

用户打开软件、进入记录、输入内容并保存。数据库提交成功后，系统才显示成功并将记录加入时间轴。

Moment 是一次主动保存的记录。以下为字段示意，完整字段及类型以附录 AA.2 为准。

```text
Moment
{
 id,
 createTime,
 content,
 type,
 tags,
 importance,
 privacyLevel
}
```

技术实现：Web：Vue3，TypeScript，Pinia，IndexedDB，移动：Kotlin，Room数据库

REC-001：输入“完成第一次硬件设计”并保存，核查正文、创建时间和记录 ID；关闭并重新打开应用后再次读取。预期记录完整，重复点击保存不会生成重复对象。

保存异常处理：内容为空时说明原因并停留在编辑器；数据库写入失败或空间不足时保留输入。重复点击和网络状态变化不应影响已提交对象，未提交操作不得标为成功。

## 6.2 语音记录模块

### 6.2.1 功能目标

语音用于不便打字的场景，如散步时想到项目方案、睡前产生想法或实验结束后补记发现。交互应清楚显示开始、录制和结束状态，并允许取消。

### 6.2.2 用户使用流程

用户主动点击语音入口后，系统申请麦克风权限。获准后开始录音并显示计时；用户结束录音后，保存原始音频和元数据。转写是另行选择的能力，转写文本不替代原始音频。

### 6.2.3 数据结构

原始音频和转写文本分别保存，通过附件 ID 与 Moment 关联。转写需要标注来源、生成时间和修订状态；用户可修正识别错误。以下为关系示意。

```json
{
"id":"xxx",
"type":"audio",
"time":"2026-10-15 23:00",
"audio":"local/path/audio001.wav",
"text":"刚刚想到未来硬件应该..."
}
```

### 6.2.4 技术方案

Web 音频录制：使用：MediaRecorder API，流程：浏览器 → 麦克风流 → MediaRecorder → Blob → IndexedDB

Android：使用：MediaRecorder；使用 AudioRecord 时需另接编码器处理原始音频。保存：AAC/Opus格式。原因：压缩率高。

### 6.2.5 语音转文字

首个语音版本只要求可靠录音和播放。后续比较本地识别或系统识别的可行性；系统识别是否使用网络须在启用前明确。授权、转写失败和缓存清理与录音保存分别处理。

### 6.2.6 验收标准

AUD-001：录制 30 秒语音，结束后核查音频附件与记录关联。重新启动应用并完整播放，预期内容可读、时长合理、文件未损坏。

录音异常处理：权限拒绝时可改用文字；来电、切到后台、设备断开等中断场景分别验证可恢复内容。保存失败时先保留临时音频，显示重试或删除选项；上传和转写不作为本地录音完成条件。

AUD-002：完成离线环境准备后断网录音，预期原始音频仍可保存和播放；未部署离线识别时，转写保持待处理状态，不阻塞录音保存。

## 6.3 图片记录模块

### 6.3.1 功能目标

图片附件用于保存项目截图、设计草图、旅行照片和实验结果，与相关文字记录建立关联。

### 6.3.2 用户流程

用户选择相册图片或主动拍摄，预览后保存。权限被拒、读取失败或空间不足时，应保留现有正文并说明失败原因。

### 6.3.3 数据设计

附件元数据与文件内容分开管理。数据库保存附件 ID、记录 ID、类型、大小、校验值和存储引用；内容通过各端存储适配器读写。

```text
Moment
 |
Attachment
 |
image001.jpg
```

数据库：Attachment表：

| 字段 | 说明 |
| --- | --- |
| id | 附件编号 |
| moment_id | 所属记录 |
| path | 文件路径 |
| type | 图片/音频 |
| size | 大小 |

Web 原型可将 Blob 保存在 IndexedDB，并独立保存附件元数据；Android 与桌面端采用应用私有文件空间或加密对象存储。导入和拍摄通过各端文件或媒体接口完成，保存引用不依赖开发机器的绝对路径。

图片默认不上传。生成分享副本时默认移除位置等敏感 EXIF 信息，并提示处理范围；原始文件是否保留由用户选择。IMG-001 验证图片可显示、可删除，且在关闭同步和外部处理时不产生上传请求。

## 6.4 标签系统

### 6.4.1 为什么需要标签

标签帮助用户组织不断积累的记录。早期由用户主动创建和选择；后续 AI 可提出标签建议，但需用户确认才能写入正式关联。

### 6.4.2 默认标签

可提供学习、项目、创造、家庭、旅行、想法和情绪等参考标签。用户可修改或删除，保存记录不要求选择标签。

### 6.4.3 数据结构

Tag表：

```text
Tag
id
name
create_time
```

关联表：

```text
Moment_Tag
moment_id
tag_id
```

### 6.4.4 使用流程

用户保存“完成示例图像项目优化”时，可选择项目和技术标签。已有记录也能在详情页补充或移除标签。

TAG-001：创建“项目”标签并关联一条记录，重新打开后核查显示和筛选结果；移除关联后，该记录不再出现在该标签筛选中。

## 6.5 时间轴系统

### 6.5.1 功能目标

时间轴展示用户自己的经历，按事件时间浏览，并允许切换到记录创建时间。基础版不设置公开互动功能。

### 6.5.2 页面结构

页面提供年份选择和时间筛选，每条记录显示时间、正文摘要和已选标签。点击后可读取完整正文与附件。

```text
2026.10.15
22:30
想到时己硬件方向
标签：
产品设计
```

### 6.5.3 数据加载策略

时间轴采用分页或游标加载，首屏先读取例如 20 条记录，继续浏览时按需加载。列表规模较大时再使用虚拟列表；排序需以稳定字段和记录 ID 共同确定，避免分页重复或漏项。

空列表与加载失败：没有记录时显示记录入口；读取失败时保留当前列表和筛选条件，提供重试。用户编辑返回后维持当前位置，新增记录按排序规则加入，避免跳回顶部。

### 6.5.4 验收标准

TIMELINE-001：准备 10,000 条记录，在登记的参考设备上测量冷启动首屏加载，目标不超过 3 秒。继续浏览、筛选和返回时检查是否出现明显卡顿、重复或遗漏；高规模测试另见 7.12。

## 6.6 搜索系统

### 6.6.1 基础搜索

0.1 提供正文关键词检索。例如输入“示例图像项目”，返回含该关键词且当前可访问的记录，结果支持打开原文。

### 6.6.2 技术方案

Web 原型通过 IndexedDB 存储适配器实现受控关键词过滤；SQLite 端可从 LIKE 查询起步，数据规模增大后评估 FTS5。明文搜索索引是否落盘须与加密方案一起设计，不能把 SQL 查询直接用于 Dexie。

### 6.6.3 未来升级

AI 阶段可增加语义搜索，例如用“第一次做项目”检索相关部署记录。语义相似仅用于候选排序，结果仍需展示原文、时间和来源。

### 6.6.4 验收

SEARCH-001：准备 5,000 条记录和预先标注的关键词样例，测量查询到结果显示的耗时，目标不超过 1 秒；同时验证空结果、特殊字符、中文输入和权限过滤。

## 6.7 数据导出系统

### 6.7.1 核心理念

导出使用户能够把记录带离当前应用。可恢复备份与用于阅读的文件需要分别标注用途。

JSON 用于数据迁移和恢复，包含格式版本、记录、关系及附件清单。下面只示意单条正文，不能作为完整恢复包。

```json
{
"moment":"今天完成项目"
}
```

Markdown 用于离线阅读和编辑，可保留时间、正文及附件引用。

PDF 用于阅读或主动分享，不应被标为完整恢复备份。

### 6.7.2 导出流程

用户在数据管理中选择导出范围、用途和格式，预览清单后生成文件。导出完成须显示文件名、对象数量和校验结果，并提醒用户保管敏感副本。

EXPORT-001：先导出完整恢复包，在独立测试环境中导入，比较记录 ID、正文、关联、附件数量与校验值；确认恢复成功后，才测试卸载或清除数据。禁止先删除唯一副本再验证备份。

恢复入口：用户选择迁移包后，先预览格式版本、记录数量和附件清单，再决定合并或替换。默认不覆盖当前资料；不支持的版本、认证失败或损坏附件应阻止提交并说明问题。

## 6.8 数据删除系统

删除需要明确处理范围和恢复条件，不能只把记录从页面隐藏。操作前区分回收站、永久删除和外部副本。

普通删除把记录移入回收站，保留期限由产品策略说明，用户可在期限内恢复。

永久删除清理当前可控制范围内的正文、附件、关系、全文索引、向量和缓存。同步删除按墓碑及设备确认规则处理；已导出或交付他人的副本另行管理。

DELETE-001：永久删除后，从时间轴、搜索、附件查看和 AI 检索分别核查残留；同步与备份测试按各自范围登记。搜索不到只是其中一项检查，不能据此证明所有副本均已擦除。

## 6.9 隐私中心

隐私中心集中展示数据位置、处理状态和授权范围，让用户能够查看和调整相关设置。

### 6.9.1 数据透明

页面分别显示本地记录、附件、AI 派生数据和同步状态。显示值应由实际配置和运行状态读取，不使用固定宣传文案。示例如下。

```text
文字记录：
本地
图片：
本地
AI分析：
本地
云同步：
关闭
```

### 6.9.2 权限管理

页面展示麦克风、照片、通知等系统权限，并说明如何在系统设置中修改。同步与外部 AI 授权分别管理；关闭同步不自动表示应用没有任何网络请求。

### 6.9.3 分享控制

分享前展示接收对象、记录和附件清单、时间范围、处理方式以及副本的撤回限制。用户确认后才生成或发送选定资料。

MVP 功能分期清单：以下为软件 MVP 系列的规划清单。Alpha 0.1 以文字记录、时间轴、编辑删除、关键词检索、JSON 导入导出与隐私状态为基础；语音、图片和标签放入 0.2。勾选状态必须由实际测试填写。用户功能：□ 文字记录，□ 语音记录，□ 图片附件，□ 标签，□ 时间轴，□ 搜索，□ 导出，□ 删除，□ 隐私中心

技术能力：□ 本地运行，□ 离线可用，□ 本地数据库，□ 基础加密，□ 数据可迁移

# 7 个人经验数据库与回忆系统

[返回总目录](../README.md)

返回目录  ·  阅读导航

计划在第 3 至 6 个月推进经验组织。前置条件是记录、保存、检索和迁移闭环已通过验收。本阶段增加个人经验数据库（Personal Experience Database），让用户把离散记录关联为主题、项目和成长过程。

## 7.1 为什么需要个人经验数据库

一条经历可能与多年后的活动有关。例如，用户从接触无人机、购买设备到参与航拍项目，再转向相关软件开发。时间排序展示事件先后，主题和项目关联进一步帮助用户回顾长期兴趣。关联不自动表示因果关系。

Experience Graph 表示用户确认的经验关联网络。每条边需能追溯到建立方式和相关记录。

## 7.2 经验对象模型升级

保留 Moment 作为基本记录，新增 Experience 组织长期主题。Project 和 Goal 分别管理持续项目与目标，不替代原始记录。

### 7.2.1 Moment 瞬间记录

```json
{

```

### 7.2.2 Experience 经验节点

表示：长期形成的主题。例如：“软件开发能力”。它可能来自：多个Moment。结构：

结构要素：Experience；Moment；Attachment。

### 7.2.3 Project 项目对象

针对：长期项目。例如：示例图像项目。保存：开始时间；目标；版本；里程碑。数据：

### 7.2.4 Goal 目标

# 8 共证式 AI 智能理解系统

[返回总目录](../README.md)

返回目录  ·  阅读导航

AI 默认关闭。权限过滤必须覆盖预处理、向量化、检索、生成和缓存；云计算与密文同步分别授权。授权模式见附录 AA。

AI 规划在第 6 至 12 个月开展，前置条件是记录、关系和数据权限已稳定。分析只使用本次授权且与问题相关的资料；当记录不足时应说明信息不足，避免据少量文本建立稳定的人格画像。

## 8.1 为什么不是一开始加入 AI

过早引入 AI 分析会增加数据不足、解释失真和用户过度信任结果的风险。以下示例用于说明设计约束，不代表所有 AI 产品的实际行为。

数据不足：用户仅写“今天很累”时，系统无法判断是睡眠、工作还是其他因素所致。应保留原话，必要时询问是否补充背景。

推断过度：完成一个项目不能直接证明领导能力。模型输出必须说明依据所覆盖的事件和时间范围。

解释依赖：长期把模型评价呈现为确定结论，可能影响用户判断。时己采用共证式 AI（Co-validated AI），将候选解释和用户反馈分开保存。

## 8.2 共证式 AI 核心流程

传统：

流程：用户数据；AI分析；结果。

时己：

流程：用户记录；AI观察；提供依据；提出可能解释；用户确认/修改；形成个人理解。

## 8.3 AI系统总体架构

流程：用户经验数据库；数据筛选层；Embedding向量化；本地向量数据库；检索相关经历；大语言模型；洞察结果；用户反馈；经验模型更新。

## 8.4 AI数据来源设计

AI 访问控制以记录范围、用途、处理位置和授权状态共同判断，不能只看单一隐私等级。

完全私密记录默认排除在 AI 处理范围之外，包括预处理、向量化、检索和缓存。

本地分析需用户选择用途和记录范围，例如只允许最近一个月的项目记录参与月度总结。

向专业人员分享与向外部 AI 服务发送数据是不同授权。分享给医生的资料不会因此自动开放给 AI。统一授权契约见附录 AA.7。

## 8.5 数据预处理模块

### 8.5.1 文本清洗

保留原文，另建分析副本处理格式和切片。例如“今天真的特别开心！！！”的原始表达继续可读；处理版本、规则和来源 ID 需要保存，便于核查。

流程：Original Text；Analysis Copy。

### 8.5.2 时间信息处理

分析使用创建时间、事件时间和已确认的项目关联。项目自动识别只能作为建议，未经确认不改写正式关系。

## 8.6 Embedding 向量化系统

### 8.6.1 为什么需要Embedding

普通搜索：关键词匹配。例如：搜索：“压力”，找不到：“最近感觉事情太多。”，向量搜索：理解语义。可以找到：相似表达。

### 8.6.2 技术方案

文本： → Embedding模型 → 向量，例如：

流程：今天感觉压力很大；[0.234,0.543,...]。

### 8.6.3 模型选择

优先：本地模型。方案：轻量：BGE-small，BGE-base，更高：大型Embedding模型。

## 8.7 向量数据库设计

用于保存：经验之间的语义关系。结构：

```text
VectorRecord
id
moment_id
embedding
created_time
```

例如：一条记录：

```text

对应：

```

## 8.8 RAG检索增强生成

这是时己AI核心技术。

RAG 先检索本次授权的相关记录，再用这些资料生成候选总结。例如回答“过去一年我有什么变化”时，先筛选时间范围和来源，再生成带记录引用的结果。检索增强不能保证消除错误，仍需来源核查与用户反馈。

## 8.9 AI洞察类型设计

类型一：周期总结，例如：每周。输出：

```text
本周记录：
12条
主要主题：
学习
项目
重要事件：
完成测试版本
```

类型二：趋势发现，例如：AI：“过去三个月，你多次记录关于隐私保护的想法。”，依据：记录：A，B，C，可能原因：项目需求影响；兴趣方向变化。请确认。

类型三：经验连接，例如：AI发现：兴趣主题 → 项目实践 → 作品成果，形成：兴趣发展路径。

## 8.10 洞察卡设计

AI输出不能直接成为事实。采用：洞察卡。格式：

```text
标题：
发现一个可能趋势
AI观察：
最近半年你多次记录软件项目。
依据：
2026.8 项目记录
2026.9 开发记录
2026.10 规划记录
可能解释：
你正在建立长期技术方向。
其他可能：
只是近期课程要求。
你的看法：
[符合]
[修改]
[不符合]
```

## 8.11 用户反馈系统

用户可认可、修订或拒绝洞察。系统保存反馈状态、时间和修订内容；拒绝后默认不继续用于后续解释，是否删除该洞察由用户选择。用户认可不把模型推断自动转为客观事实。

反馈异常处理：保存反馈失败时保留用户修订内容并提示重试。来源记录被删除或权限改变后，洞察应标记失效或重新生成；反馈本身不恢复已被撤销的访问权。

## 8.12 AI安全限制

禁止一：人格判断，错误：“你是完美主义者。”，正确：“你的记录中多次出现对质量控制的关注。”

禁止二：心理诊断，错误：“你可能患有焦虑症。”，正确：“你多次记录压力相关内容，如果影响生活，可以考虑寻求帮助。”

禁止三：替代决策，错误：“你应该辞职。”，正确：“你的记录显示你长期关注职业方向，可以进一步思考。”

## 13.6 记录功能实现流程

## 13.10 安全第一版设计

禁止：直接保存密码。保存：密码派生参数、盐与经过 KEK 包装的 DEK；不保存原始密码。

功能测试连续执行 1,000 次记录操作，比较已提交对象与读取结果，目标无已确认记录丢失；同时注入写入失败和强制关闭，验证失败提示与恢复状态。

准备 10,000 条记录测试时间轴首屏，工程优化目标为 2 秒。与 6.5 的 3 秒 MVP 基线分别登记，均需注明设备、版本和冷启动条件。

安全测试检查持久化文件、附件、索引和日志是否出现声明为加密的明文内容。检查时说明设备锁定与密钥解锁状态；测试不能覆盖未声明的保护范围。

## 13.20 工程总结

工程重点是长期可靠的数据管理和可核查的 AI 辅助流程。架构、界面、授权和测试应共同支持记录完整、分析可追溯、迁移可验证和问题可恢复。

## 14.5 加密安全架构

这是整个项目核心。

### 14.5.1 安全目标

静态加密用于降低设备丢失或存储文件泄露时的资料暴露风险，前提是攻击者未取得可用解密密钥。

保护范围必须说明设备是否锁定、密钥是否已解锁。静态加密无法保证抵御已控制运行中终端的攻击者。

验收应核查密文、密钥存储、认证失败处理和日志残留，按实际验证范围描述保护能力。

### 14.5.2 加密流程

流程：用户密码；密钥派生；主密钥；数据加密密钥；AES-GCM；数据库。

### 14.5.3 密钥设计

采用：双层密钥。

第一层：用户密码。用户记忆。

第二层：随机生成密钥。真正加密数据。结构：

流程：Password；Key Encryption Key；Data Encryption Key；User Data。

使用随机 DEK 加密数据，使用密码派生的 KEK 包装 DEK。修改密码时重新派生 KEK 并重包 DEK；先验证新包装可解密，再替换旧包装，避免中断造成无法恢复。

## 14.6 备份恢复设计

备份恢复需让用户明确保存了什么、能否恢复，以及丢失密码和恢复材料的后果。

### 14.6.1 备份文件

可使用 .shiji 作为完整加密备份容器的扩展名。容器应包含格式版本、数据库对象、附件、清单和校验信息；扩展名本身不保证完整或加密。

### 14.6.2 恢复流程

导入前检查格式和容量，输入有效解密材料后验证认证信息与清单，在临时区解析和校验，再事务提交。失败时不改写当前数据；成功后对比对象和附件，并显示恢复结果。

恢复验收：使用独立测试库验证正确密码、错误密码、损坏容器、缺失附件、不支持版本和中断导入。成功恢复后核查数量、关系与文件校验；失败时确认旧库仍完整可用。

### 14.6.3 防止用户忘记密码

设计：恢复密钥。但是必须：告诉用户：“密码遗忘且没有有效恢复路径时，无法解密全部数据。”

## 14.7 同步安全设计

未来：多端。错误方式：服务器保存明文。禁止。正确：端到端加密。流程：设备A：加密 → 服务器：密文 → 设备B：解密。服务器不知道：用户记录内容。

## 14.8 威胁模型分析

数据库文件泄露：使用经验证的加密持久层，并检查密钥、索引及日志是否暴露内容。

服务端被攻击：同步仅保存密文和必要元数据，同时限定元数据、认证和密钥分发的保护范围。

威胁3：AI误判。解决：事实与洞察分离。

威胁4：第三方窥探。解决：权限控制。

设备丢失：撤销后续同步访问，并按策略轮换密钥；不承诺清除已下载到离线设备的资料。

## 14.9 安全验收标准

SEC-001：取得应用持久化文件，预期未持有有效密钥时无法还原受保护内容；另查附件、索引和日志残留。

SEC-002：错误密码。要求：无法解密。

SEC-003：关闭网络。要求：核心功能正常。

SEC-004：删除数据。要求：在声明的删除范围内无法通过应用恢复；外部备份另行管理。

## 14.10 本阶段完成标准

完成后：时己拥有：数据能力：□完整经验模型，□长期存储，□项目管理，□AI隔离，安全能力：□本地加密，□备份恢复，□权限控制，扩展能力：□支持多端，□支持硬件，□支持AI

## E.1 安全设计目标

时己处理的数据具有特殊性：它不是普通账号数据。不是简单：用户名。密码。订单。而是，一个人的：经历；想法；成长轨迹；情绪变化；长期行为模式。因此安全目标不是，“不被黑客攻击”。而是，即使系统面对攻击、错误配置、设备丢失，用户仍然拥有对个人经验的控制权。

## E.2 威胁模型方法

采用：STRIDE模型。包括：Spoofing（身份伪造），Tampering（数据篡改），Repudiation（抵赖风险），Information Disclosure（信息泄露），Denial of Service（服务阻断），Elevation of Privilege（权限提升）

## E.3 攻击者模型设计

### E.3.1 普通攻击者

能力：低。例如：获取设备文件。查看软件目录。目标：读取用户记录。防护：数据加密；权限隔离。

### E.3.2 高级攻击者

能力：中高。例如：服务器入侵。数据库泄露。目标：批量获取用户数据。防护：端到端加密；最小化服务器数据。

### E.3.3 恶意内部人员

例如：拥有服务器权限的人。风险：最高。防护：核心原则：服务器不保存明文。

### E.3.4 用户身边人员

这是现实中非常常见。例如：家人。朋友。同事。可能：直接打开设备。防护：应用锁；权限管理；分享控制。

## E.4 数据生命周期安全

流程：创建；本地保存；分析；同步；备份；删除。

每个阶段：都有安全要求。

## E.5 本地数据安全

### E.5.1 风险

手机丢失。电脑被盗。硬盘拆除。

### E.5.2 防护方案

数据库加密：SQLite：不能直接保存明文。采用：SQLCipher。结构：普通：

流程：database.db；content。

安全：

流程：database.db；encrypted data。

### E.5.3 文件加密

图片。音频。不能：直接放文件夹。错误：

/images/photo001.jpg

任何人可以打开。正确：

/encrypted/file001.bin

必须通过程序解密。

## E.6 密码与密钥安全

这是最困难部分。

### E.6.1 为什么不能只靠密码

用户密码：容易弱。例如：123456。因此，增加：密钥派生。流程：

流程：用户密码；Argon2id；密钥；AES-GCM；数据。

### E.6.2 Argon2id设计

作用：增加暴力破解成本。攻击者：不能快速尝试密码。参数：根据设备调整。例如：手机：中等。电脑：较高。

### E.6.3 恢复密钥设计

可研究恢复密钥或恢复短语，但格式、校验、包装方案和恢复验证必须明确，不能直接套用任意词数。用户需妥善保存恢复材料；密码遗忘且没有有效恢复路径时，系统无法解密资料。

## E.7 云同步安全模型

未来：用户可能需要多设备。但是，不能退回传统云模式。

### E.7.1 错误方案

用户数据： → 服务器 → AI分析，禁止。

### E.7.2 正确方案

设备A：原始数据 → 本地加密 → 上传密文 → 服务器存储 → 设备B下载 → 本地解密。

## E.8 服务器安全设计

服务器只负责：用户认证；密文同步；版本管理。服务器不知道：用户记录内容。数据库：保存：

```json
{
"user":"001",
"encrypted_blob":
"9af82..."
}
```

## E.9 AI安全模型

AI是最大风险之一。

### E.9.1 风险

AI读取：过多数据。生成：错误结论。

### E.9.2 防护

权限隔离：AI不能：直接访问数据库。流程：

流程：AI请求；权限层；数据筛选；AI。

### E.9.3 AI输出审查

所有洞察：必须包含：来源。例如：错误：你是一个焦虑的人。正确：最近10条记录中，有3条提到压力事件。

## E.10 第三方隐私保护

问题：用户记录可能包含别人。例如：“今天和朋友讨论项目。”，里面可能包含：朋友姓名。

### E.10.1 原则

用户拥有：自己的经历。但不拥有：他人的隐私。

### E.10.2 分享检测

未来：分享前提示。例如：发现：手机号。提示：“该内容可能包含第三方信息。”

## E.11 硬件安全模型

Moment设备：风险：丢失。

### E.11.1 本地存储加密

Flash：加密。

### E.11.2 蓝牙安全

采用：BLE Secure Connection。

### E.11.3 固件安全

防止：恶意修改。采用：Secure Boot。

## E.12 软件供应链安全

长期项目必须考虑。风险：第三方依赖漏洞。措施：依赖锁定：例如：package-lock。

定期扫描：工具：Dependabot。

版本记录：每次发布：记录依赖。

## E.13 安全测试方案

SEC-001 数据库攻击测试：方法：复制数据库文件。尝试读取。结果：失败。

SEC-002 密码攻击测试：方法：错误密码10000次。结果：记录密钥派生参数与实测耗时，检查错误口令被拒；该测试不能证明不可破解。

SEC-003 权限测试：关闭AI权限。测试：AI请求。结果：拒绝。

SEC-004 网络监听测试：抓包。结果：没有明文隐私数据。

SEC-005 删除测试：删除记录。检查：数据库。缓存。备份。结果：在本次可控制的存储范围内完成删除，并检查残留副本。

## E.16 隐私验收清单

正式发布前：必须全部通过。

用户控制：□ 用户知道数据在哪里，□ 用户可以导出，□ 用户可以删除，□ 用户可以关闭AI

数据安全：□ 本地加密，□ 密钥安全，□ 同步加密

AI安全：□ 来源可追溯，□ 用户可修改，□ 不做诊断

商业安全：□ 不出售数据，□ 不隐藏数据用途

## E.17 本附录总结

时己真正的安全理念：不是，“我们保护你的数据。”，而是，从架构上减少任何人拥有你数据的机会。这也是时己区别于很多AI产品的根本：很多产品思考：“如何利用更多数据创造价值。”，时己思考：“如何让用户在获得价值的同时，仍然拥有数据主权。”

## F.1 AI设计目标

时己中的AI不是传统意义上的聊天机器人。它不是，陪聊机器人；心理分析师；人格测试工具；决策代理。它的角色：Personal Experience Assistant：个人经验辅助系统。核心任务：帮助用户：找到过去；看见变化；整理经验；形成自己的理解。

## F.2 AI行为总原则

所有模型必须遵守：第一原则：不创造用户没有提供的信息：例如：用户记录：今天完成代码。AI不能说：你从小热爱编程。因为：没有依据。

第二原则：不把推断伪装成事实：错误：你是一个高度自律的人。正确：你的记录中多次出现持续完成长期任务的情况，这可能反映出较强的目标坚持能力。

第三原则：不替用户做人生决定：错误：你应该选择软件开发方向。正确：你的记录显示软件开发占据较多时间，你可以进一步考虑是否将其作为长期方向。

第四原则：永远允许用户反驳AI：AI不是老师。用户不是学生。关系：共同探索。

## F.3 系统级 Prompt

这是所有模型基础约束。

```text

帮助用户理解自己过去留下的经验记录。
必须遵守：
1. 用户原始记录属于事实层。
2. AI生成内容属于推断层。
3. 推断必须明确表达不确定性。
4. 所有重要结论必须提供依据。
5. 用户拥有最终解释权。
禁止：
- 人格诊断；
- 心理诊断；
- 医疗判断；
- 强制建议；
- 制造不存在的经历。
回答格式：

（基于记录）

（多个可能）
待确认：
（询问用户）
```

## G.1 UX设计目标

时己最大的挑战不是技术。而是，如何让一个包含数据库、AI、安全、硬件的复杂系统，在普通用户眼中变得简单。用户不应该感受到：数据模型；加密算法；AI权限；向量数据库。用户应该感受到：我只是保存了一个瞬间。

## G.2 UX核心原则

原则1：记录必须足够快：人的想法消失很快。如果记录需要：打开App。登录。选择分类。填写标题。用户会放弃。目标：秒进入记录状态。理想流程：打开 → 点击 → 输入 → 完成。

原则2：不要求用户整理：很多软件的问题：要求用户：分类。标签。归档。但是记录当下：用户没有精力。时己：先记录。后整理。例如：用户输入：“今天想到硬件不要做手环。”，保存。以后：用户可以整理。

原则3：AI不打扰用户：很多AI产品：不停提醒：“我发现……”，“你有没有注意……”，容易造成压力。时己：默认：安静。AI主动出现：必须低频。

原则4：用户永远知道发生了什么：尤其隐私。例如：AI分析前：显示：本次分析将读取过去30天的12条记录，仅在本地运行。

## G.3 首页设计

目标：打开即记录。首页结构：

结构要素：2027年1月1日；[ 记录此刻 ]；最近：；10分钟前；想到新的硬件设计；昨天；完成项目测试。

## G.4 记录入口设计

核心按钮：记录此刻：不要：“新建日记”。原因：心理压力。“记录”像：保存一个瞬间。

## G.5 文字记录体验

流程：点击按钮 → 输入框出现 → 键盘自动打开 → 输入 → 保存。不要：强制填写：标题。分类。心情。

## G.6 语音记录体验

手机语音采用点击开始、再次点击结束的流程，显示录音状态、计时和取消入口。权限被拒或录制中断时说明状态；不要求用户在驾驶等需要专注的活动中操作。

```text

00:15
再次点击结束
```

结束后验证音频可读，再保存附件和关联记录。失败时保留可恢复内容并提示重试；仅在保存完成后显示成功。

## G.7 图片记录体验

图片不是，上传分享。而是，经验附件。例如：用户拍：白板。代码截图。设计稿。系统：保存。关联。

## G.10 AI洞察卡UI设计

这是最重要的交互。普通AI：直接聊天。时己：卡片。示例：

以洞察卡作为主要交互，便于并列展示观察、依据、解释和反馈。是否辅以对话形式通过可用性测试决定，不能假定卡片本身就能消除权威感。

## G.13 密钥恢复UX设计

这是最大难题之一。

恢复提示需清楚说明材料的用途与丢失后果，避免只要求用户抄写一串陌生词语后直接继续。

正确设计：分阶段。第一次：简单提示。你的记录只属于你。如果设备损坏，我们无法替你恢复。第二次：引导备份。第三次：验证备份。

## G.14 备份演练设计

先引导保存恢复材料，再在独立测试资料上验证解密与恢复。抽查字符只能确认用户保存了材料的一部分，不能代替实际导入演练；演练不得删除唯一数据副本。

## G.18 首次使用流程

目标：5分钟理解。步骤：第一步：欢迎。说明：时己帮助你保存自己的经历。

第二步：第一次记录。立即体验。

第三步：解释隐私。不是长篇协议。而是，三个问题。问题1：数据在哪里？回答：默认只在你的设备。问题2：AI会读取吗？回答：需要你的允许。问题3：别人能看到吗？回答：默认不能。

## G.19 普通用户语言转换

技术语言：“个人经验主权。”，用户语言：“你的记录属于你。”，技术：“事实与推断分离。”，用户语言：“AI会告诉你它为什么这么想。”，技术：“端到端加密。”，用户语言：“别人拿到文件也看不到内容。”

## G.20 无障碍设计

特殊群体需要。老人：大按钮。少文字。儿童：简单表达。视障：语音操作。

## G.21 UX验收标准

UX-001：第一次使用。要求：30秒内完成第一次记录。

UX-002：普通用户理解隐私。测试：询问：“你的数据在哪里？”，正确率：90%以上。

UX-003：用户愿意持续使用。测试：30天。

UX-004：用户不会感觉被AI评价。调查：AI是否带来压力。

## G.22 UX总结

时己真正的设计哲学：不是，让用户学习如何使用复杂系统。而是，让复杂技术隐藏在简单体验之后。最终状态：用户看到：一个按钮。一次记录。一段回忆。背后：是数据库。加密。AI。硬件。多年积累。

## R.1 数据治理目标

时己处理的数据具有特殊性质。它不是普通互联网数据。它可能包含：人生经历；家庭关系；工作项目；学习过程；情绪变化；健康相关信息；对未来的规划。因此，数据治理不能只考虑：“如何存储”。必须考虑：谁可以访问、为什么访问、访问后如何负责。

## R.2 数据治理核心原则

原则1：数据默认属于用户：系统中的所有经验数据：默认：用户所有。平台：不是拥有者。只是：服务提供者。

原则2：最小化收集：时己不应该问：“还能收集什么？”，而应该问：“实现功能最低需要什么？”，例如：记录功能：需要：文字。不需要：GPS。不需要：通讯录。不需要：摄像头权限。

原则3：用户主动授权：任何扩大数据使用范围的行为：必须：明确授权。例如：AI分析：第一次：询问。以后：用户可以关闭。

原则4：可撤回：授权：不是永久出售。用户任何时候：可以撤回。

## R.3 数据分类体系

建立：五级数据分类。

D0级：公开数据，特点：用户主动公开。例如：公开项目介绍。权限：公开。

D1级：普通个人数据，例如：普通笔记。学习记录。权限：用户本人。

D2级：敏感经验数据，例如：家庭经历。个人关系。权限：严格控制。

D3级：高度敏感数据，例如：健康相关。心理状态记录。权限：最高保护。

D4级：核心身份数据，例如：恢复密钥。身份认证。权限：后台服务不可读取；客户端仅在授权解锁后使用。

## R.4 数据生命周期管理

流程：产生；保存；使用；分析；分享；删除。

每一步：都有控制。

## R.25 本附录总结

时己最大的隐私创新：不是，“我们承诺保护你的数据。”，而是，让系统设计本身减少需要相信系统的程度。传统模式：用户相信平台。时己模式：用户控制系统。这也是个人经验主权真正落地的基础。

## AA.2 统一术语与数据字段

| 字段 | 统一含义 | 校验要求 |
| --- | --- | --- |
| id | 记录或对象的稳定唯一标识 | 导入 同步与附件关联使用同一 ID |
| createdAt | 首次创建时间 UTC Unix 毫秒 | 建立后保持稳定 |
| updatedAt | 最后一次编辑时间 UTC Unix 毫秒 | 不得单独作为冲突胜负依据 |
| eventAt | 用户填写的实际发生时间 | 可为空 与创建时间区分 |
| eventPrecision | millisecond minute day month unknown | 防止把仅有日期记录显示为精确事件 |
| type | text image audio video hardware | 采用字符串枚举 跨端不要混用数字映射 |
| revision | 对象修订版本 | 与 baseRevision 比较 冲突保留双方 |
| deletedAt | 删除状态与时间 | 同步删除保留墓碑 防止离线记录复活 |
| privacyLevel | 内容敏感等级 | 不直接代替 AI 权限或分享权限 |
| aiPolicy | none localAllowed | 外部模型另设具体请求授权 |
| sourceKind | user report device derived | 区分用户自述 外部证据 设备事件与推导结果 |

Moment 是记录；Experience 是主题；Project 是持续项目；Goal 是目标。Project 的状态统一为 planned、active、paused、completed、archived，避免正文与附录 A 中整数含义不同。关系必须由用户主动建立或确认，系统建议关系保留来源和确认状态。

原始用户表达属于自述资料，不自动等同于已被外部证实的事实。Fact 层保存原话、来源和时间；Observation 保存可复现的统计方法与范围；Insight 保存模型生成的候选解释。用户认可洞察不改变其来源类别。

**数据库示意补充**

正式关系数据库至少补充主外键、NOT NULL、枚举约束和复合唯一键；moment_tag、project_moment、insight_source 使用关系复合主键；删除记录时明确关联清理和派生数据失效。SQLite 的外键执行需开启并验证。Dexie 使用等价的事务与索引规则。

文字 content 与敏感附件在加密持久层保存密文。privacyLevel、encrypted 标志和 file_path 都不是保护机制。明文元数据的最小范围必须列入威胁模型；全文索引和向量也可能暴露原始语义。

## AA.3 本地存储与离线使用

第一步，创建 Repository 接口，将页面与 IndexedDB 分离；页面只调用 create、update、query、remove、export 和 import，不直接遍历底层表。第二步，用 Dexie 定义版本与索引；第三步，对一次保存的相关对象使用事务。数据库写入成功后才显示保存成功；失败时保留输入并提供重试。

第四步，实现 PWA 应用壳缓存和离线入口。IndexedDB 只负责数据，不能保证网页第一次离线访问就能打开；首次在线加载与应用壳缓存完成后，再测试断网重启。第五步，显示存储占用和最近成功备份时间，处理配额不足、持久存储申请被拒和用户清除站点数据。[1]

本地优先不等同于永久保存。浏览器会管理配额和存储清理；持久存储申请不能代替备份。更换域名或协议可能改变存储来源，部署迁移前必须提供导出、导入与验证路径。[1]

图片与音频使用附件 ID 关联 Blob 或应用私有文件，导出包中使用相对路径。Web 无需强行套用原生文件系统；Android 与桌面端采用私有存储与加密文件。公开分享前生成脱敏副本，保留原件的策略由用户选择。

音频录制必须检查权限、设备可用性、浏览器支持格式、录音时长和保存失败。Android 可使用 MediaRecorder 直接录制压缩音频；AudioRecord 采集原始数据时另接编码器。转写结果保存为派生文本，原音频保持独立来源。[2]

## AA.4 密钥 加密与恢复契约

创建数据密钥 DEK，用它保护本地记录和附件。用户密码通过带盐的密钥派生流程生成 KEK，KEK 用于包装 DEK；更改密码只重新包装 DEK。保存包装版本、KDF 名称、盐和参数，不能只写“保存 Hash”作为完整方案。

AES-GCM 每次加密必须在同一密钥下使用唯一 IV，建议使用 96 位 IV。密文包保留算法版本、IV 与认证信息，并将对象 ID 和格式版本绑定到附加认证数据；篡改、错误密码或认证失败时停止导入，不能展示部分损坏内容。[3]

Web 通过 Web Crypto 执行已支持的算法；Argon2id 若作为候选，需要经审查的实现和设备参数测试，不能假设浏览器原生提供。禁止自制加密算法。正式发布前固定实现、依赖版本、参数和测试向量；跨端使用相同格式验证加解密。[4]

恢复密钥是独立解锁路径，生成和显示都在客户端。验证用户保存的是可用备份，而不只是看过恢复码。密码遗忘且没有任何有效恢复路径时，服务端不能凭账户登录恢复加密数据；已解锁设备和有效恢复包的处理按既定流程验证。

锁定时移除应用可访问的解密状态和派生明文缓存，后台日志不记录内容。静态加密保护离线文件，并不保证已经解锁的受控终端安全。设备撤销阻止后续同步，不能远程抹除已经被导出或复制的明文。

## AA.5 导入导出 备份与迁移

完整备份包含 manifest、记录、标签、关系、项目、附件与必要设置；manifest 至少包含 formatVersion、schemaVersion、exportedAt、时间单位、对象数量与校验信息。JSON 便于迁移，但带附件的完整备份需保留附件二进制。Markdown 和 PDF 属于阅读副本，不作为完整恢复格式。

导出前读取一致的数据库快照；生成成功后校验数量、附件存在性和引用。导出明文包时说明包含哪些记录和附件，由用户选择；加密备份使用独立版本标识，恢复密钥不放在同一个未保护包内。

导入步骤：选择文件 → 校验格式和大小 → 解密并验证 → 校验 ID 与关系 → 预览新增、重复与冲突数量 → 用户选择合并或恢复到空库 → 在暂存区事务提交 → 再次校验。未知新版本、损坏文件和附件缺失不得导致现有数据库被覆盖。

同 ID 同 revision 同内容作为重复导入，不重复创建；同 ID 不同内容保留冲突并要求选择。先在暂存区完成导入，失败时回滚。每次重大 Schema 升级前生成备份，迁移脚本可重试，回滚方案必须与实际数据格式兼容。

恢复演练：在第二个独立环境恢复测试包，比较记录、标签、项目、关系、附件数量及附件校验值，检查关键样例、时间精度和隐私设置。演练报告保存版本与结果，不依靠“文件能打开”判断完整恢复。

## AA.6 删除与派生数据失效

普通删除移入回收站；永久删除清理当前可控制范围内的记录、附件、索引、向量、AI 上下文、缓存和临时文件。共享附件采用引用计数，避免删除仍被其他记录使用的内容；垃圾清理必须可审计。

同步启用时保存删除墓碑，离线设备重新上线必须先拉取删除状态，不能将旧记录当作新增上传。墓碑何时回收由所有设备确认、设备撤销和备份策略共同决定；未经确认不得过早清除。

备份和已经交给第三方的文件属于不同删除范围。界面列出本机已删、同步待确认、离线设备待处理和外部副本不受控状态。删除回执只证明本次操作执行情况，不承诺任意存储介质的物理不可恢复。

记录被修改、删除或取消 AI 授权时，相应向量、检索缓存、总结和洞察标记为失效。洞察引用显示来源修订版本；旧洞察不得继续表现为基于当前完整数据的结果。

## AA.7 API 与权限执行

| 能力 | 本地接口 | 未来 HTTP 映射 |
| --- | --- | --- |
| 创建记录 | createMoment(input) | POST /v1/moments |
| 查询记录 | listMoments(filter cursor limit) | GET /v1/moments |
| 编辑记录 | updateMoment(id baseRevision patch) | PATCH /v1/moments/{id} |
| 删除记录 | deleteMoment(id baseRevision mode) | DELETE /v1/moments/{id} |
| 关键词搜索 | searchMoments(query filter cursor) | GET /v1/search?q=... |
| 创建导出 | exportBundle(scope format) | POST /v1/exports |
| 校验导入 | validateImport(bundle) | POST /v1/imports/validate |
| 执行分析 | requestInsight(scope grantId) | POST /v1/insights |
| 同步事件 | applySyncBatch(batch) | POST /v1/sync/batches |

用户 ID、记录归属与授权由可信的执行层决定，不能接受请求体中 permission:true 作为授权依据。读取权限必须在查询前过滤；生成 AI 上下文前再校验；长任务执行中发现授权撤回则停止并清理临时上下文。

返回结构统一包含 data、error 和 requestId。错误代码至少包含 VALIDATION_ERROR、NOT_FOUND、PERMISSION_DENIED、STORAGE_FULL、CONFLICT、UNSUPPORTED_VERSION 与 CORRUPT_BACKUP。错误消息面向用户说明可执行的下一步，日志使用请求 ID 和对象 ID，不记录私人内容。

分页使用稳定排序键，建议 eventAt 或 createdAt 加 id；筛选条件和 cursor 绑定。修改或删除携带 baseRevision，冲突返回双方版本，不直接按设备时间覆盖。导出、删除和同步批次支持幂等标识，重试不会重复操作。

## AA.8 AI 授权 生成与共证流程

授权拆成四类：本地处理、端到端密文同步、外部 AI 请求、向指定人员分享。隐私等级用于帮助识别敏感程度，不能把“可分享”自动解释为“允许模型分析”。每次授权明确对象、用途、范围、有效期和撤回方式。

本地 AI 流程：用户选择范围 → 权限筛选 → 对授权内容预处理 → 建立或读取索引 → 检索 → 构建受限上下文 → 生成结构化候选 → 验证来源 ID 与修订 → 展示依据和不确定性 → 用户确认、修改或拒绝 → 保存反馈。

共证表示共同澄清解释，不是确认客观真相。洞察至少保存 modelId、modelVersion、promptVersion、sourceIds、sourceRevisions、generatedAt、scope 与 feedbackStatus。用户修改保存为用户反馈，不悄悄改写模型原始输出。

云增强与密文同步的区别：同步服务器可以只保存密文；普通云推理通常需要在服务端读取输入，仅使用 TLS 或上传前加密并不能让一般模型直接理解密文。云请求需预览将发送的原文或摘要、服务对象与处理政策，用户另行授权。若没有明确支持的隐私计算方案，不宣称服务端完全看不到输入。

模型输出中的 source 必须对应本次上下文真实记录；引用存在仍不能证明解释正确。无资料时返回不足，来源矛盾时并列展示，用户拒绝后不反复强调同一判断。单纯使用“可能”或设置词库不能替代幻觉与越权评估。

评估至少覆盖来源准确、越权读取、无资料拒答、统计误读、用户纠错和删除后的缓存失效。来源准确率按人工核验的陈述计算；用户认可率仅反映体验，不当作正确率。分离开发集与最终测试集，保存模型参数、设备、样本、错误类型和复测结果。

## AA.9 同步冲突与设备撤销

每条变更包含 objectId、revision、baseRevision、deviceId、operationId 和操作类型。服务器同步密文和必要元数据；设备解密并执行本地约束。设备时间用于显示，不作为唯一冲突依据。

两个设备从相同 baseRevision 编辑同一条记录时，保留两份候选及共同原版本，提示用户合并；合并生成新的 revision。上传可重试，但 operationId 必须幂等；删除墓碑优先阻止旧数据复活，恢复删除记录作为新的显式操作处理。

新增设备通过已授权设备或恢复流程取得加密密钥，不将裸密钥上传普通同步存储。设备丢失后撤销同步令牌，必要时轮换未来数据密钥；已经复制的明文和旧密钥不能通过账户撤销自动收回。
